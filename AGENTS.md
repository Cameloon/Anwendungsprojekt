# AGENTS.md

## Stack

- **Frontend:** Vite + React 18 + TypeScript (loose — `strict: false`, `noImplicitAny: false`)
- **Backend:** Convex (serverless BaaS, 26 tables in schema)
- **UI:** Tailwind CSS + shadcn/ui + Radix UI primitives
- **Auth:** Clerk (JWT, `convex/auth.config.ts`) with automatic demo mode fallback
- **Build tool:** `@vitejs/plugin-react-swc` (SWC, not Babel)
- **Package manager:** Bun (npm also works)
- **Testing:** Vitest — jsdom + @testing-library/react (frontend), `convex-test` + `edge-runtime` (Convex backend, `tests/convex/`)
- **Linting:** ESLint (flat config `eslint.config.js`)
- **Path alias:** `@/` → `./src/`

## Key Commands

```bash
bun install                         # Install dependencies
bun dev                             # Dev server on port 8080
bun build                           # Production build
bun build:dev                       # Dev mode build
bun preview                         # Preview production build
bun lint                            # ESLint (flat config)
bun test                            # Vitest run (headless)
bun test:watch                      # Vitest watch mode
bun run update-test-status          # Run tests + update docs/test-uebersicht.md
npx convex dev                      # Sync Convex schema/functions (run in parallel to bun dev)
npx convex deploy                   # Production Convex deploy
```

Dev requires **two parallel terminals**: `bun dev` (port 8080) + `npx convex dev`.

## Conventions

### Demo Mode
`IS_DEMO` in `src/lib/demoMode.ts` auto-detects when `VITE_CLERK_PUBLISHABLE_KEY` or `VITE_CONVEX_URL` is missing. When true, the app uses localStorage for dummy auth/profile instead of Clerk/Convex. `useAuth` hook in `src/hooks/useAuth.tsx` switches between `useDemoAuth()` and `useClerkBackedAuth()` via `IS_DEMO`.

### Auth & Access Flow
1. Clerk sign-up → `EnsureProfile` creates Convex profile with `role: "user"`
2. Onboarding → `OnboardingDialog` forces `displayName`, `studienfach`, `matrikelnummer`, `hochschule`, `kurs`
3. After onboarding → profile `status: "pending"`, user sees "Freischaltung ausstehend"
4. Admin approves/rejects via `admin.ts` mutations → `status: "active"` / `"rejected"`
5. Admin users (`role: "admin"`) bypass approval → always `"active"`
6. `ProtectedRoute` uses `getAccessStatus` query → shows onboarding/pending/rejected/active states
7. Navbar adapts: before approval only "Zugang freischalten", after full nav

### Convex
- **Always read `convex/_generated/ai/guidelines.md`** before writing Convex code (overrides training data). This file is generated by the Convex tooling (e.g. on first `npx convex dev` sync / `npx convex ai-files install`) — it does not exist in a freshly cloned repo before that has run once.
- Available skills: load via `skill` tool or run `npx convex ai-files install`
- Run `npx convex dev` to sync schema and generate API bindings
- `ctx.auth.getUserIdentity()` for server-side auth; NEVER accept userId as function arg
- Profile fields: `kurs` is uppercased on save; `role` defaults to `"user"`
- `convex/migrations.ts` collects one-off data migrations/cleanups run manually via `npx convex run migrations:<name>` against a deployment (e.g. `renameJahrgangToKurs` for the historical `jahrgang` → `kurs` field rename). These have already been applied to the current dev deployment (`kurs` is the live field everywhere; `jahrgang` fields remain only as deprecated fallbacks in `schema.ts`) — they're kept for reference and for migrating a fresh/other deployment, not as a pending setup step.

### Testing
- Tests in `tests/` (not `src/test/`) — `tests/**/*.{test,spec}.{ts,tsx}`
- Setup file: `tests/setup.ts` (mocks localStorage, matchMedia, scrollIntoView; guarded with `typeof window !== "undefined"` so it no-ops for Convex backend tests)
- Convex backend tests live in `tests/convex/` and use `convex-test` (`convexTest(schema)`, `t.withIdentity({ subject })`) — these files start with `// @vitest-environment edge-runtime` to opt out of the default `jsdom` environment; requires `@edge-runtime/vm` and `server.deps.inline: ["convex-test"]` in `vitest.config.ts`
- `bun run update-test-status` runs all tests and writes results to `docs/test-uebersicht.md`

### Layout
- Navbar: `fixed top-0`, pages use `pt-32 md:pt-24`
- Footer: sticky flexbox (not fixed)
- Mobile navbar ~108px due to bottom nav strip
- 1600ms splash screen on boot (`SplashScreen` component)

## Convex AI Guidelines

When working on Convex code, **always read `convex/_generated/ai/guidelines.md` first** for important guidelines on how to correctly use Convex APIs and patterns. The file contains rules that override what you may have learned about Convex from training data.

Convex agent skills for common tasks can be installed by running `npx convex ai-files install`. Skills are available at `.agents/skills/` and can be loaded via the `skill` tool.
